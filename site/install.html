Install

Get telltale.

It checks Debian 12 and 13 and Ubuntu 22.04 and 24.04, on amd64 and arm64. Every binary is static and runs on any of them.

Releases on GitHub

Which download

Every release has these files, and SHA256SUMS for all of them. <arch> is amd64 or arm64.

FileWhat it is
telltale-carry_<version>_linux_<arch>.tar.gzThe collector build: scan, snapshot, accept, fetch-refs and collect. Take this one to carry telltale to machines. About 14 MB unpacked. It cannot run the server.
telltale_<version>_linux_<arch>.tar.gzThe full build: everything above plus server and mcp. About 23 MB unpacked.
telltale_<version>-1_<arch>.debThe server package: the full build, the collectors for both architectures (what the server copies to machines), a systemd unit and an example configuration.

Check the download on a machine you trust before you unpack it:

$ sha256sum --check --ignore-missing SHA256SUMS

Each release file also has a signed build provenance attestation: it says the file was built by the project's release workflow from the tagged commit. The GitHub CLI checks it:

$ gh attestation verify telltale-carry_0.1.0_linux_amd64.tar.gz --repo donaldsteele/telltale

Carry it

Unpack it on a machine you trust, then copy the binary to the machine you want to check:

$ tar xzf telltale-carry_0.1.0_linux_amd64.tar.gz
$ scp telltale web01:

On the machine, as root (without root it still runs, and lists what it had to skip):

$ sudo ./telltale scan                                  # no snapshot yet
$ sudo ./telltale snapshot --out /media/usb/web01.snap  # once you believe it is clean

snapshot asks for a passphrase and encrypts the file. Keep it off the machine: a snapshot left there could be edited by whoever you are looking for. Next time, bring it back:

$ sudo ./telltale scan --snapshot /media/usb/web01.snap
$ sudo ./telltale scan --snapshot /media/usb/web01.snap --html web01.html

The exit code says what it found: 0 nothing, 1 notes or weak settings only, 2 tampering or a backdoor sign, 3 the scan could not run. A finding you meant to have is accepted with telltale accept ID --snapshot FILE, using the ID the report prints under it.

A machine with no network

A scan downloads the packages it checks from the distribution's archive. For a machine cut off the network, collect on it, build a reference bundle on a machine that has a connection, and carry the bundle back:

$ sudo ./telltale collect > web01.json                     # on the isolated machine
$ telltale fetch-refs --for web01.json --out web01-refs    # on a machine with network access
$ sudo ./telltale scan --refs web01-refs                   # back on the isolated machine

The server

Run the server on a small machine of its own: it holds SSH access as root to every machine it visits. With the package:

$ sudo apt install ./telltale_0.1.0-1_amd64.deb
$ sudo install -m 0640 -o root -g telltale /etc/telltale/telltale.toml.example /etc/telltale/telltale.toml
$ sudoedit /etc/telltale/telltale.toml     # listen: this machine's LAN address and a port
$ sudo install -m 0600 /dev/null /etc/telltale/passphrase
$ sudoedit /etc/telltale/passphrase        # the passphrase that encrypts the database
$ sudo systemctl enable --now telltale
$ sudo journalctl -u telltale              # the setup code and the certificate fingerprint

Open https://<listen address>/, check that the certificate fingerprint matches the one in the log, and set the admin password with the setup code. Then, for each machine:

  1. Enrol it by name and address, and compare its SSH host key fingerprint with what the machine's own console says before you confirm.
  2. Add the two snippets the server shows: an authorized_keys line for root that works only from the server's address, and a Match Address block that lets root log in with a key from that address only.
  3. Press Check now, read the first report, and when you believe the machine is clean, take the snapshot. Every later visit is compared with it.

Visits happen daily by default. docs/server.md covers enrolment, the sshd block and why, backups, alerts to bubbles and the MCP server.

Build from source

You need Go 1.26 or newer.

$ git clone https://github.com/donaldsteele/telltale
$ cd telltale
$ go build -o telltale ./cmd/telltale                   # the full build
$ go build -tags collector -o telltale ./cmd/telltale   # the collector build

Every command and flag is in docs/usage.md.
